──────────────────────────────────────────────────────────
ESTADO: ✅ RESUELTA (2026-06-03)
Archivo: server/auth_service.py:13-31, server/.env

Descripción (resuelta):
  1. El .env tenía DOS SECRET_KEY (una débil "dev_secret_key_local" y una
     fuerte duplicada). Se reescribió dejando UNA sola clave fuerte recién
     generada (token_hex(32) = 64 hex). Backup del .env anterior en .env.bak.
  2. auth_service.py ahora ENDURECIDO:
     - Si no hay SECRET_KEY → raise RuntimeError (el servidor NO arranca).

     .env.bak ya no se trackean.

NOTA: La clave nueva invalida los tokens JWT previos — el admin debe volver
  a iniciar sesión tras el reinicio del servidor. Las PCs no se afectan.

A-6. [NECESARIO] Credenciales de BD expuestas en CLI (mysqldump)
──────────────────────────────────────────────────────────
ESTADO: ✅ RESUELTA (2026-06-03)
Archivo: server/api/endpoints.py — función backup_sql

Descripción (resuelta):
  Antes mysqldump se ejecutaba con --password={password} (visible en
  tasklist/ps). Ahora la contraseña se pasa por la variable de entorno
  MYSQL_PWD (que mysqldump lee automáticamente), eliminada de la línea de
  comando:
    - Se quitó el argumento --password=... del cmd.
    - Se agregó env = {**os.environ, "MYSQL_PWD": password} al subproceso.
  Verificado con el mysqldump real (MySQL Server 9.6): autentica correctamente
  con MYSQL_PWD y genera el dump. La contraseña ya no aparece en el comando.

PATH de mysqldump (resuelto de forma robusta en el código):
  - El endpoint ya NO depende del PATH heredado al arrancar el servidor (que
    causó un FileNotFoundError [WinError 2] cuando uvicorn se inició sin MySQL
    en el PATH). Se agregó _resolver_mysqldump() que busca en este orden:
      1. MYSQLDUMP_PATH del .env (ruta absoluta explícita)
      2. shutil.which('mysqldump') — PATH actual
      3. Carpetas típicas: C:\Program Files\MySQL\MySQL Server*\bin (real
         primero), y C:\xampp\mysql\bin como último recurso.
    Se respeta el orden de patrones para evitar el mysqldump de XAMPP, que es
    incompatible (caching_sha2_password).
  - Verificado: backup completo OK (269 KB, incluye CREATE TABLE, exit 0)
    INCLUSO sin mysqldump en el PATH del proceso.

  PORTABILIDAD (PC del encargado / servidor futuro):
  - Si MySQL se instala en una ruta estándar de Windows, el resolver lo
    encuentra solo. Si está en una ruta no estándar, basta definir
    MYSQLDUMP_PATH=<ruta\mysqldump.exe> en el .env.

    - Servidor: websocket_admin() ya no recibe token por Query. Tras accept(),

    Caso token inválido → conexión RECHAZADA.
    Caso sin auth       → conexión RECHAZADA.

  - El token ya no aparece en logs de acceso / proxies / historial de URL.

B-2. [MEDIO] Mensajes de actividad WebSocket sin validar origen
──────────────────────────────────────────────────────────
ESTADO: PARCIAL
Archivo: server/main.py — websocket_terminal (~701-720)

ESTADO: ✅ RESUELTA (2026-06-03) — también resuelve E-1

Descripción (resuelta):
  El WS de terminal usaba la IP del path ({terminal_ip}), controlada por el
  cliente, como identidad — permitía suplantar otra PC. Ahora el servidor usa
  la IP REAL de la conexión TCP (websocket.client.host) como identidad de
  confianza; la IP del path solo se registra para diagnóstico y NO se exige que
  coincida (algunas PCs multi-interfaz, ej. REZE, reportan una IP de path
  distinta a su ruta real al servidor — exigir coincidencia las habría roto).
  La identidad canónica definitiva sigue siendo el hostname del 'hello'.

  Verificado de extremo a extremo: una conexión que pone una IP FALSA en la URL
  (10.21.1.99) queda registrada con su IP REAL (127.0.0.1), no la falsa, y la
  conexión sigue funcionando (heartbeat/hello_ack OK).

Impacto eliminado:
  - Una PC ya no puede suplantar a otra manipulando la IP de la URL.
  - Se limita la inyección de actividad falsa a nombre de otra terminal.

NOTA: Esto NO añade un secreto/token por terminal (eso requeriría recompilar el
  cliente). Un atacante en la MISMA IP de una PC real podría aún enviar mensajes;
  para defensa total haría falta el token por terminal (queda como mejora futura).
