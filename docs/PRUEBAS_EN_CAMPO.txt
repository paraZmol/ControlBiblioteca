───────────────────────────────────────────────────────────────────
  A. MODO OFFLINE DEL KIOSCO (cliente C# — rediseñado hoy)
───────────────────────────────────────────────────────────────────
  Contexto: el flujo cambió. Ahora el alumno llena sus datos normal y el
  encargado activa el modo offline con el atajo + PIN al final.

  A-1. Flujo offline nuevo — activación por el encargado
  ───────────────────────────────────────────────────────
  Pasos:
    1. En una PC cliente, desconectar la red (desenchufar cable o cortar wifi)
       para simular que el servidor no es alcanzable.
    2. Esperar a que el kiosco detecte la desconexión (indicador en rojo
       "Desconectado").
    3. En la pantalla de login del alumno: escribir un DNI válido (8 dígitos).
    4. Verificar que el campo "Razón de uso" solo deja elegir "Otros
       (Especificar)" y que el campo de texto aparece para escribir el motivo.
    5. Escribir un motivo y dar clic en "INGRESAR".

  Resultado esperado:
    - Aparece el mensaje: "Sin conexion al servidor. Contacte al encargado."
    - La PC NO se desbloquea todavía.
    - La pantalla se ve IGUAL que siempre (sin la interfaz fea del modo offline
      anterior).

  A-2. El encargado autoriza con el atajo + PIN
  ───────────────────────────────────────────────
  Pasos (continúa de A-1):
    1. El encargado presiona el atajo configurado (por defecto Ctrl+Alt+F11).
    2. Aparece un diálogo que pide SOLO el PIN del encargado (NO vuelve a pedir
       DNI ni motivo — ya los puso el alumno).
    3. Ingresar el PIN correcto.

  Resultado esperado:
    - El kiosco se desbloquea con el DNI y motivo que el alumno ya había escrito.
    - El alumno puede usar la PC.
    - En el log local del kiosco (offline_sessions.json en su carpeta) queda
      registrada la sesión offline.

  A-3. PIN incorrecto
  ────────────────────
  Pasos: en el diálogo del PIN, escribir un PIN equivocado.
  Resultado esperado:
    - Mensaje de PIN incorrecto, la PC sigue bloqueada, permite reintentar.

  A-4. Reconexión con sesión offline activa
  ──────────────────────────────────────────
  Pasos:
    1. Con una sesión offline activa (de A-2), volver a conectar la red.
    2. Esperar a que el kiosco reconecte al servidor.
  Resultado esperado:
    - Si el DNI es válido y no está baneado: la sesión continúa sin cortar al
      alumno; aparece un aviso "Conexion restaurada. Sesion sincronizada."
    - Si el DNI NO está registrado o está baneado: cuenta regresiva de 3 minutos
      con el mensaje correspondiente, luego se bloquea.
    - En el panel (Nodos), la PC aparece como activa con el alumno.

  A-5. CONFIRMAR LA CORRECCIÓN DE G-5 (la bandera atascada — ya corregida)
  ─────────────────────────────────────────────────────────────────────────
    Contexto: antes había un bug donde, si la sesión offline se cerraba por el
    timeout de gracia ANTES de reconectar, una bandera interna quedaba atascada y
    la PC NO se podía bloquear remotamente. Se CORRIGIÓ el 2026-06-10. Esta
    prueba confirma que la corrección funciona (requiere el .exe recompilado).
  [ ] Pasos:
        1. Activar modo offline (A-1, A-2).
        2. Dejar pasar el tiempo de gracia SIN reconectar hasta que la PC se
           bloquee sola.
        3. Reconectar la red.
        4. Desde el panel, intentar BLOQUEAR esa PC.
      Resultado esperado: la PC SÍ se bloquea desde el panel (corrección OK).
      Si NO se bloquea → la corrección no tomó efecto; verificar que el .exe
      desplegado sea el recompilado hoy.


───────────────────────────────────────────────────────────────────
  B. AUDITORÍA EN BASE DE DATOS (nuevo)
───────────────────────────────────────────────────────────────────
  Contexto: ahora queda registrado en la BD quién hizo cada acción
  administrativa, visible en Configuración → Auditoría (solo superadmin).

  B-1. La pestaña existe y es solo-superadmin
  ─────────────────────────────────────────────
  Pasos:
    1. Iniciar sesión como SUPERADMIN.
    2. Ir a Configuración. Verificar que existe el subtab "Auditoría".
    3. Cerrar sesión, iniciar como ADMIN normal.
    4. Ir a Configuración.
  Resultado esperado:
    - Superadmin VE el subtab "Auditoría".
    - Admin normal NO ve el subtab "Auditoría".

  B-2. Se registran las acciones de bloqueo/apagado
  ───────────────────────────────────────────────────
  Pasos (como superadmin o admin):
    1. Bloquear una PC desde Nodos.
    2. Apagar otra PC.
    3. Bloquear toda la sala.
    4. Ir a Configuración → Auditoría.
  Resultado esperado:
    - Aparecen 3 registros nuevos con: tu usuario, tu rol, la acción (Bloquear
      terminal / Apagar terminal / Bloquear toda la sala), el objetivo (nombre
      de la PC) y la fecha/hora.

  B-3. Se registran ban y levantamiento de ban
  ───────────────────────────────────────────────
  Pasos:
    1. Banear a un alumno (Alertas → Baneados → Nuevo ban).
    2. Levantar ese ban.
    3. Ir a Configuración → Auditoría.
  Resultado esperado:
    - Dos registros: "Banear alumno" y "Levantar ban", con el DNI del alumno en
      el objetivo y tu usuario.

  B-4. Se registra el ciclo de vida de PERSONAS (lo que pediste)
  ─────────────────────────────────────────────────────────────────
  Pasos:
    1. Crear un estudiante nuevo (Base de Datos → Estudiantes → Nuevo).
    2. Editar ese estudiante.
    3. Eliminar ese estudiante.
    4. Crear / editar / eliminar un registro de Personal.
    5. Ir a Configuración → Auditoría y filtrar por las acciones de personas.
  Resultado esperado:
    - Aparecen los registros: Crear estudiante, Editar estudiante, Eliminar
      estudiante, Crear personal, Editar personal, Eliminar personal — todos con
      tu usuario, el DNI afectado y la hora.

  B-5. Filtros de la auditoría
  ──────────────────────────────
  Pasos: en Configuración → Auditoría, usar los filtros:
    - Escribir un usuario en el filtro "Usuario".
    - Elegir una acción en el desplegable.
    - Poner un rango de fechas (Desde / Hasta).
  Resultado esperado:
    - La tabla se filtra correctamente. La paginación (Anterior/Siguiente)
      funciona si hay muchos registros.

  B-6. Cambios de configuración y resets quedan registrados
  ────────────────────────────────────────────────────────────
  Pasos:
    1. Cambiar el PIN del backdoor o del modo offline (Configuración → Backdoor).
    2. Descargar un backup SQL (Configuración → Copia de seguridad).
    3. Ir a Configuración → Auditoría.
  Resultado esperado:
    - Registros "Config backdoor" / "Config offline" (SIN mostrar el PIN, solo
      el hecho del cambio) y "Backup SQL".
